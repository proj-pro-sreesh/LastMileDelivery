# Hosted Deployment Guide

The backend ships with a [Render Blueprint](../render.yaml) that provisions the API plus a managed
PostgreSQL database. The frontend is a static Next.js export served from Vercel. Everything below
uses the free tiers — no paid resources are created.

## 1. Push the repository to GitHub

```bash
git init && git add . && git commit -m "Initial commit"
gh repo create lastmile-delivery --private --source=. --push
```

## 2. Create the PostgreSQL database on Render

1. Go to <https://dashboard.render.com> → **New → Blueprint** and select this repository.
   Render reads `render.yaml` and creates both the web service and the database.
2. (Manual alternative) **New → PostgreSQL**, name it `lastmile-delivery-db`, plan *Free*.

## 3. Wire environment variables

The blueprint sets these automatically; verify under *Service → Environment*:

| Variable | Value |
| --- | --- |
| `ENVIRONMENT` | `production` |
| `DATABASE_URL` | *(linked from the database's connection string)* |
| `SECRET_KEY` | *(auto-generated by the blueprint)* |
| `CORS_ORIGINS` | `https://<your-frontend>.vercel.app` |
| `NOTIFICATIONS_MODE` | `mock` |
| `EMAIL_PROVIDER` / `SMS_PROVIDER` | `mock` |

Render hands out `postgres://...` URLs; the app normalizes them to
`postgresql+psycopg://...?sslmode=require` at startup, so no manual editing is needed.

## 4. First deploy of the API

Trigger **Manual Deploy → Deploy latest commit**. The start command runs
`alembic upgrade head` before booting uvicorn, so the schema migrates automatically on every
deploy.

## 5. Verify the health check

```bash
curl https://lastmile-delivery-api.onrender.com/health
# {"status":"ok","database":"ok"}
```

The interactive docs live at `https://<your-api>.onrender.com/docs`.

## 6. Seed demo data

From your machine, with `heroku`-like port forwarding not needed — just run the seed script
against the remote DB once:

```bash
DATABASE_URL="postgresql+psycopg://user:pass@host/lastmile_delivery?sslmode=require" \
  ../.venv/bin/python scripts/seed.py
```

Copy the connection string from *Dashboard → lastmile-delivery-db → Connections → External*.
This creates the admin user (`admin@lastmile-demo.com` / `Admin@123`), zones, areas, rate cards,
COD rates and demo agents.

> Free-tier databases expire after 30 days; re-seed after restoring from backup if needed.

## 7. Deploy the frontend to Vercel

1. <https://vercel.com/new> → import the same repository.
2. **Root Directory**: `frontend`.
3. Environment variable: `NEXT_PUBLIC_API_URL = https://<your-api>.onrender.com`
   (it is baked in at build time, so set it before the first build).
4. Deploy. Add the resulting `*.vercel.app` URL to the backend's `CORS_ORIGINS` and redeploy
   the API once so browsers stop being blocked.

## 8. Smoke-test the hosted stack

```bash
API=https://lastmile-delivery-api.onrender.com
curl -s -X POST $API/auth/register -H 'Content-Type: application/json' \
  -d '{"name":"Smoke","email":"smoke@example.com","password":"Password@123","phone":"+919000000000"}'
curl -s -X POST $API/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"admin@lastmile-demo.com","password":"Admin@123"}'
```

Then log into the frontend, book an order and run auto-assign as admin.

## 9. Ongoing deploys

Both platforms redeploy on push to the default branch. Migrations run before each API boot;
frontend rebuilds bake the current `NEXT_PUBLIC_API_URL`.

### Swapping mock notifications for real email/SMS

Set `EMAIL_PROVIDER=resend` + `EMAIL_API_KEY=<resend key>` + `EMAIL_FROM=no-reply@yourdomain`,
and/or `SMS_PROVIDER=twilio` + `SMS_API_KEY=AccountSid:AuthToken` + `SMS_FROM=+15005550006`.
Secrets belong in the Render dashboard only — never committed.
